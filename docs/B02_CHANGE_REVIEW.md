# B02：AI 修改逐项核对

日期：2026-09-28。版本：桌面测试版 0.4.7。负责人：本次开发任务。

状态：已实现并同步桌面测试版，自动窗口检查、最终回归及随带运行环境复验通过。真人试用、不同系统缩放和真实账户模型验证尚未开展。

## 场景与操作

AI 返回一篇修改稿，用户只想采用部分修改。原有「应用修改」一次替换整篇，无法分别决定保留哪处原文。本轮增加「逐项核对…」，显示原文与建议，支持采用此处、保留原文和采用全部待核对。

1. 打开「AI 接入」，勾选「附上当前文档」，发送修改要求。
2. 收到可应用的整篇建议后，点「逐项核对…」。没有先点核对时，原有「应用修改」仍可一次应用整篇。
3. 选择修改块，左右对照原文与建议，再决定采用或保留。
4. 关闭核对后，可在源码编辑器按 `Ctrl+Z` 撤销、`Ctrl+Y` 重做。重新打开核对时，状态依据正文同步。
5. 满意后手动保存。关闭窗口保留已经采用的部分，剩余部分不自动采用。

核对过之后，原「应用修改」变为「采用全部待核对」，继续尊重已选择「保留原文」的块。每次采用走现有编辑回调，只改编辑缓冲，一次操作对应一次撤销，不自动保存。新请求或新对话开始新的建议；核对决策仅保存在当前助手窗口内。

首版针对桌面整篇建议；B01 选区建议沿用原范围替换。网页助手没有新增逐项入口。没有新 AI 请求格式、网络重试、聊天持久化或插件包。

## 定位与边界

按原文字符区间拼接结果，不按第一个相同字符串查找。采用前再次核对文档对象和完整正文；范围外原文、换行与重复段落原样保留。行号标为请求时的「原文第…行」。

同一段落、表格、围栏代码块和独立公式内的修改合并核对。引用定义或 HTML 标签发生修改时，保守合并整份建议并说明原因。首版不能判定所有语义依赖；用户仍需核对事实、数字、链接目标和结构。两栏直接显示 Markdown，代码和链接目标不会因渲染隐藏。

超过 3000 行、原文超过 20 万字符或超过 200 个修改块时，合并为一个块并说明原因，避免重复文本的匹配与历史占用无限增长。匹配在后台执行。

撤销/重做只接受本次采纳产生过的完整文本状态。任意手工编辑不猜测为历史状态；切换文档、关闭原文或正文出现其他变化时阻止旧建议写入，提示回到原文或重新生成。
