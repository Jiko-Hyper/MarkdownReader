### 2026-09-25 / 正式插件导出丢字（维护者人工试用发现）

- **维护者人工试用结果**：装好三个正式插件后导出 `IGBT_文献精读笔记_双TSEP温差与饱和压降.md`，反馈「转换时会出现乱码」，附了 PDF、DOCX 与截图——正文里 `23×10⁻⁶/K`、`α_Al − α_Si`、`R_eq = R_single / (n − m)` 这些位置留了空白。**这一条只有真实入口 + 真实文档才暴露得出来**：所有插件用例当时用的都是短样本文本，没有任何断言检查过“字符有没有真的画到纸上”。
- **根因**：中文正文/标题字体没有数学减号与上下标的字形，ReportLab 对没有字形的字符照画一个空的 `.notdef`（连 `stringWidth` 都给正常宽度），所以导出成功、文件正常、字符却是空白。该笔记里缺字形的字符是 `² ⁻ ⁶ ₁ ₂ −` 六个，共出现 97 次。
- **修复与验证**：`exporting.py` 按字体 `cmap` 逐字符挑字体（Times New Roman → Cambria → Segoe UI Symbol 作为回退），PDF 与 Word 共用同一套判断；用 fontTools 作为独立实现核对自读的 cmap；导出后读 PDF **文本层**、Word 逐 run 核对“字体有没有这个字形”。维护者那篇笔记重导：27 页、源文件 850 个非 ASCII 字符在 PDF 文本层里**一个都不缺**。
- **仍需人工确认（未做）**：① 打开修复后的 PDF / Word，确认这些符号的**观感**（它们现在用的是 Times New Roman 字形，与中文正文字体不完全一致）；② 打开截图那一页（第 3 页）确认不再是空白——自动比对只能证明字符在文本层与 run 里，纸面观感仍要人眼。**在这两项人工确认之前，F03/F07/F08 只记为待验收。**
