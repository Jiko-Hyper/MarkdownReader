# MDReader 下一阶段：公式写作质量与阅读设置

更新日期：2026-09-26。当前开发基线：0.2.9。本文是计划，所列功能尚未交付。

## 现状与优先级

0.2.9 已有两端「∑ 公式」入口：选中文字可插入行内/独立公式，空选区给出可替换模板；两端预览、离线 HTML 和 PDF/DOCX 插件沿用已有本机公式渲染。当前数学排版只承诺 `formula.SUPPORTED_SAMPLES` 的 TeX 子集；Word/PDF 中的公式还是图片，不能在 Word 编辑或在 PDF 检索。桌面、网页及导出稿的真实观感，尤其长公式和中文输入法下的操作，仍需要人工确认。

按以下顺序推进，上一批的失败分支和使用体验确认后再进入下一批：

1. **公式写作反馈**：在源码模式提供所选公式的即时预览与错误位置/原因；支持修改已有公式时保留选区、光标及一次撤销语义。优先解决真实文档里最常见的失败写法，再决定是否扩展 TeX 命令表。验收包括中文输入法组合、三种主题、100%/150%/200% 缩放、长公式、错误公式、代码/金额中的美元符号、切标签与保存后重开。
2. **导出可编辑性**：单独验证固定样本从 TeX 到 Office Math 的转换。只有样本在 Word 中可编辑、重开后结构不变且混排位置正确，才把可编辑公式加入 DOCX 插件；不能转换的表达式继续保留当前图片降级与原始 TeX 提示。PDF/HTML 继续保持离线可读。Microsoft 的 [数学文档](https://learn.microsoft.com/en-us/office/math/)确认 Word 把数学内容存成 OMML；具体转换仍需本项目实测。
3. **阅读舒适度**：完成旧任务 E02 的字号、行距、正文宽度设置，并记录跨桌面/网页与重启后的结果；接着用长文实测 E06 的主题切换定位与 E07 的侧栏焦点。优先保留编辑缓冲、撤销历史和正在输入的中文组合文字。

## 本次交接与验证门槛

- 先请维护者用真实窗口确认 0.2.9 的公式按钮、行内/独立预览，以及深色/护眼模式下图片与背景的接合。自动检查只证明功能连通和图像生成，不等于视觉验收。
- 公式写作反馈进入开发时，同时覆盖桌面和网页；检查后端规则、撤销、未保存标记、保存冲突与关闭确认。公式渲染错误不能改写用户 Markdown。
- OMML 先做独立样本验证，不改现有 PDF/DOCX 插件的可信包及哈希。确定可用后单独升级插件版本，保留旧版可回退。
- 仍按 `开发框架.md` 的小范围试用目标推进：优先收集真实文档的阻碍，再安排更大的数学命令覆盖；Mermaid、完整所见即所得编辑器不列入这轮交付。
