### 2.1 P01：插件与核心的明确边界

这里的“插件”指 MDReader 自身的功能扩展，不是 Codex 插件。三个插件分别打包、启用、禁用和更新；不能只是把主程序代码换到三个文件夹，启动时仍强制导入全部转换依赖。

| 归属 | 职责 | 未安装或禁用插件时 |
| --- | --- | --- |
| 核心 | 文件夹与 MD 读写、删除保护、撤销、表格、公式、主题、基础图片显示、资源授权、HTML 导出 | 正常使用，不要求任何一个插件存在 |
| `mdreader.image-insert` | 选择图片、拖入图片、粘贴截图，生成插入方案 | 不注册插图命令；已有图片仍显示，手写 Markdown 图片链接仍可用 |
| `mdreader.export-docx` | MD 文档结构到 DOCX 的转换与格式相关预检 | 不提供可执行的 Word 导出项；不影响 PDF 与 HTML |
| `mdreader.export-pdf` | MD 文档结构到 PDF 的转换、打印样式与分页 | 不提供可执行的 PDF 导出项；不影响 Word 与 HTML |

本阶段三个插件均需开发验收，但用户可按需安装。基础包不带 Word/PDF 转换引擎；插件包带各自所需依赖或明确的离线依赖包。全量试用包可同时附带三个插件包，首次启用仍由用户选择，不在启动时静默联网下载。公式阅读不得依赖 PDF 插件，导出已有图片不得依赖图片插入插件。

### 2.2 插件管理与生命周期

- 设置增加“插件”页，显示名称、版本、说明、启用状态、兼容范围、依赖状态和失败原因；支持安装本地官方插件包、启用、禁用、卸载。首版只接受维护者发布并明确认可的包，不扫描用户文档目录自动执行脚本，不做在线市场、自动更新或任意脚本安装。
- 插件清单至少有 `id`、`name`、`version`、`api_version`、`app_version_range`、`entrypoint`、`capabilities`、`dependencies`；界面只展示清单中已通过校验的命令/格式贡献，不加载插件提供的任意 HTML 或界面代码。
- 安装检查归档路径越界、链接、大小上限、重复 ID、来源与完整性；暂存验证成功后再登记。清单自称“官方”或包内自带的哈希都不构成信任证明，来源校验规则由 P01 实现记录明确。
- 发现插件只读清单，启用后按命令惰性启动；缺依赖、清单损坏或版本不兼容只禁用该插件并说明原因，不使核心启动失败。升级前兼容检查，失败保留上一可用版本；回退不能自动复活用户禁用的插件。
- 启用状态由宿主统一保存，并同步桌面和网页可用命令。禁用后立即拒绝新任务；进行中的任务先取消并等待清理，无法热卸载时显示“重启后生效”，不能让已禁用任务继续提交结果。
- 卸载仅移除插件代码和其专属缓存；绝不删除已插入图片、源 MD 或已导出文件。升级与卸载不覆盖核心设置和其他插件依赖。
- 图片粘贴由宿主在显式用户操作时读取，不能后台监视剪贴板；禁用图片插件不得影响普通文本粘贴或拖入 MD 打开文件。

### 2.3 最小接口与任务协议

接口只覆盖实际需要的两类能力：`editor.image_insert` 和 `export.format`；先做内部版本化协议，不发布通用 SDK、插件事件总线或任意编辑器扩展 API。

| 交互 | 输入 | 输出与宿主责任 |
| --- | --- | --- |
| 能力检查 | 插件清单、API 版本、依赖状态 | 宿主注册可用命令与格式；不兼容则拒绝运行 |
| 图片插入 | 用户本次选择的图片、文档身份/缓冲修订、选区、资源策略 | 插件返回附件与 Markdown 插入方案；宿主校验、落附件并作为一次撤销提交文本 |
| 导出预检 | 不可变文档结构、资源快照、格式选项 | 核心检查通用资源与路径，插件返回格式特有的错误/降级项；由宿主统一确认 |
| 导出执行 | 已确认快照、选项、任务工作目录、任务 ID | 插件只生成临时产物并报告进度/警告；宿主验证格式、复查目标修订、执行最终替换 |
| 取消与失败 | 任务 ID、取消/超时信号 | 停止工作进程，丢弃过期结果，清理本任务暂存；保留原文和原目标 |

任务必须绑定文档身份、缓冲修订和调用入口。等待插件时若用户换标签、修改正文或关闭文档，不能按旧光标向新内容插图；拒绝过期结果并允许用户重新发起。附件写入与正文提交沿用 F03 的失败清理规则。导出继续使用启动时快照，不能混入之后的编辑。

首版采用宿主管理的独立工作进程执行插件任务，约定带任务 ID 的结构化请求、进度、结果和错误；宿主不向插件传递 Tk 控件、网页 DOM、可变文档对象或任意核心服务对象。工作进程超时、异常退出或错误结果只结束该任务，宿主保持可用；结果路径、文件类型及大小再次验证，拒绝工作目录外的产物。

图片附件和最终导出路径的实际提交由核心服务负责，插件不能通过业务接口绕过授权、覆盖确认或撤销保护。能力声明和独立进程**不是操作系统沙箱**，首版可信插件代码仍可能具有当前用户的系统权限；不宣传支持安全运行不可信第三方插件。将来开放第三方安装需另立隔离与信任方案，本轮不做。

### 2.4 P01 验收门槛

验证无插件、分别只启用一个插件、三个同时启用及重启后的状态；卸载插图插件后旧图片仍可读、可被任意导出插件内嵌；缺 PDF 依赖不影响 DOCX。覆盖清单损坏、重复 ID、不兼容、插件异常/超时、运行中禁用、升级失败、安装包越界和结果越界。

桌面与网页同一能力状态，隐藏或禁用的界面入口之外，服务端也须拒绝失效命令并保持现有会话/来源校验。无插件时核心可以启动、编辑、保存、渲染图片/公式和导出 HTML；这些用例是插件机制完成的前提，不是可跳过的可选验收。

## 3. F01：真正打开用户的文件夹

### 使用流程

提供“打开文件夹”，选择后显示该目录下的 Markdown 树。“打开原文件夹”与已有“导入到项目”是两个明确入口：前者直接读写原件、不复制；后者保留原有导入语义，不静默迁移已有项目。

- 文件树菜单提供“新建 Markdown”“刷新”“在资源管理器中打开”“从列表移除此文件夹”。最后一项只移除应用记录，不删除磁盘目录。
- 新建时选择父目录与名称，默认补 `.md`；成功后立刻在原目录创建空文件并打开。后续输入仍遵循现有保存/恢复规则，不因新建而启用自动保存。
- 校验空名称、Windows 保留名、非法字符、大小写重名、尾部空格/点和路径越界；同名时要求改名，不覆盖。检查与实际创建之间有竞争时，创建必须再次拒绝已存在目标。
- 支持子目录与大小写不同的 `.md` 扩展名。文件身份采用“已授权根目录 + 规范化相对路径”，不同根目录的同名文件不能混在一起。
- 根目录登记、阅读位置和其他应用状态保存在应用工作区；不在用户资料目录悄悄创建管理配置或复制整份资料。

### 持续更新与外部修改

监听目录变化或采用后台增量轮询，合并短时间内重复事件；不能在每次键入时全目录扫描。窗口重新激活与手动刷新做兜底。切换/关闭文件夹时停止对应监听，避免句柄和定时器累积。

目标：在本地磁盘、约 1,000 份普通 MD 的测试目录中，外部新增/删除通常 2 秒内显示；记录机器、规模和实测延迟，网络盘与可移动盘单列限制。扫描期间界面仍能编辑，不把目标数字直接写成通过结果。

| 外部事件 | 必须表现 |
| --- | --- |
| 新建、批量复制、编辑器临时文件替换 | 最终树与磁盘一致；临时中间状态不反复弹窗 |
| 修改已打开且无未保存编辑的文件 | 提示可重新加载，保留合理阅读位置，不打断输入法 |
| 修改有未保存编辑的文件 | 保留缓冲；保存时仍做版本冲突检查，不静默重载 |
| 删除或移动已打开文件 | 显示原文件已不存在；保留未保存内容并允许另存，不自动创建原路径 |
| 根目录掉线、权限不足、扫描失败 | 显示暂不可访问；不把扫描错误当作“所有文件被删除”清空状态 |

路径授权继续通过现有服务执行。默认不跟随越出根目录的符号链接/目录联接，阻止循环扫描；网页不能用任意绝对路径参数扩大授权。删除、创建和资源读取在执行前重新检查最终目标，不能只信任文件树显示的路径。

## 4. F02：删除会影响本地文件，必须明确且可恢复

首版按单文件实现，不提供整个用户根目录的递归删除。按钮使用“删除本地文件…”，不得混用“移除记录”。每次删除都提示，不提供“不再询问”。

建议确认内容：

> 将删除本地文件“学习笔记.md”，并移入 Windows 回收站。它会从原文件夹消失，不只是从 MDReader 列表中移除。其他文档和附件不会删除。  
> 完整路径：所选文件的实际完整路径  
> 操作：取消 / 移入回收站

“取消”为默认焦点；关闭弹窗或按 Escape 等同取消。存在未保存修改时先提供“另存修改后继续 / 放弃修改并继续 / 取消”；放弃分支在最终确认中再次说明尚未保存内容也会丢弃，不能将回收站宣传为能找回未保存缓冲。

执行约束：

- 沿用现有回收站能力，不新增绕过确认的删除入口。回收站不可用、文件占用、只读或权限失败时保留列表与编辑缓冲，展示原因；不得自动永久删除。
- 确认后、执行前校验路径和文件修订；如果被外部替换，重新确认，不删除确认之后出现的新版本。记录仍无法消除的系统级竞态限制。
- 成功后更新两端文件树、最近列表/收藏状态、阅读位置引用，并关闭已处理未保存状态的对应标签；失败不假装成功。
- 不删除图片、同目录其他文件、空父目录或根目录。即使某个附件看似无人使用，本轮也不自动清理。
- 同一会话其他入口若仍有未保存编辑，保留为“原文件已删除”的缓冲，只允许明确另存/恢复；不能因自动保存、监听或恢复快照而悄悄重新创建原文件。
- 恢复快照区分意图删除与意外丢失：明确放弃的旧快照不在重启后自动复活；仍需保留的缓冲只能由用户选择恢复到新位置。

若以后增加批量删除，另做清单、数量、逐项结果及部分失败处理，不复用单文件弹窗隐瞒影响范围。

## 5. F03：图片插入插件与核心预览

按“文件选择 → 文件拖放 → 剪贴板截图”分小步交付，均列为本阶段范围；PNG/JPEG 为首批保证格式，其他格式识别后明确支持或拒绝。沿用已有附件上传和授权机制；E05 已完成部分只做差异补齐。

插入交互通过 `mdreader.image-insert` 注册，附件授权、提交、标准图片链接解析和双端显示属于核心。禁止插件另建直接写用户目录的保存通道；插件禁用后下述图片阅读、安全和导出资源规则仍有效。

- 插入入口位于编辑工具栏；在光标处写入标准 `![说明](相对路径)`，不引入私有 Markdown 格式。给出可编辑的替代文字。
- 草稿先确定保存位置；用户取消定位则不落附件、不改正文。直接打开的文档默认使用同目录 `assets/`，既有托管项目延续项目附件规则，界面显示实际保存位置。
- 复制原图，不移动原件；以唯一文件名避免覆盖，并正确处理中文、空格、括号和跨目录路径。剪贴板图像落为本地文件，不把大段图片数据直接写入 Markdown。
- 文件落盘成功后才插入链接；插入失败只清理本次新建且确认未引用的附件。撤销只撤销正文链接，不删除可能已被其他文档共享的图片。
- 桌面和网页阅读模式实际显示图片，保持比例、限制到正文宽度；不能把原生端只显示 alt 文本算作完成。缺图显示说明与定位入口，不让整篇渲染失败。
- 加入图片类型、字节大小与解码像素上限，拒绝伪装文件和过大解码任务。大图用预览缓存，原图不被偷偷压缩；边界值与默认上限在实现记录中明确。
- 不自动下载远程图片、不执行 SVG/HTML 脚本，不放宽本地文件访问范围。导出验证图片已内嵌，不依赖仍在运行的本地服务。

## 6. F04：表格与轻量编辑工具

提供“插入表格”小对话框：列数、数据行数、表头和列对齐。生成标准管道表格；已有表格可增加/删除行列、修改表头与对齐。先识别可无损修改的普通表格，复杂或无法识别的结构保留源码并提示，不猜测后重写。

- 表格操作只改当前缓冲，一次插入或结构调整对应一次撤销；不自动保存。
- 单元格 `|`、反斜杠和代码标记建立明确转义用例。首版单元格只接收单行文本；多行输入提示整理，不偷偷放开原始 HTML。合并单元格、嵌套表格和 Excel 公式不在本轮范围。
- 支持粘贴矩形 TSV 文本并预览行列；不规则行、含引号或嵌入换行的复杂内容若未支持则明确提示，不静默错列。确认后才替换选区。
- 宽表在阅读界面横向滚动，不能撑破窗口。PDF/Word 导出采用换行、列宽调整或明确的宽表提示，不裁掉最后几列。
- 同批补“标题、粗体、斜体、列表、引用、代码、链接”工具栏。已有选区按规则包装，无选区插入模板；IME 组合中不强插内容，所有操作经过同一编辑命令与撤销通道。

首版不做所见即所得编辑器，也不更换整个编辑器框架。

## 7. F05：数学公式与扩展语法规则

首批支持行内 `$...$` 与独立块 `$$...$$`，提供“插入公式”和示例。保证分数、上下标、根号、希腊字母、求和、积分、矩阵和常用对齐；以固定公式样本表声明支持范围，不承诺完整 LaTeX。

- 公式识别避开行内代码、代码围栏及转义字符。单美元分隔符不能跨行，内容首尾不得为空白；货币文本、孤立 `$`、未闭合公式均建立样本，歧义时保留文本并提示用 `\$` 表示普通美元符号。
- 原始 TeX 始终留在 Markdown 中；格式错误呈现可读错误与原始表达式，不清空正文、不阻止保存其他内容。
- 网页优先验证 KaTeX 的本地资源方案；桌面先验证同源公式输出转本地缓存图片并嵌入预览的方案，记录基线、DPI、暗色主题、长公式横向布局。若所选方案无法离线或分发，不把“仅网页能看”标成双端完成，也不强行把全应用改为 WebView。
- 样式、脚本、字体和渲染依赖随包提供，禁用需要信任的 TeX 命令，限制宏展开与输出大小。缓存键包含表达式、字号、缩放、主题和渲染器版本，避免旧图错色。
- 公式节点与正文节点分开处理，不能对生成的整页 HTML 做全局正则替换。新增可信渲染产物有专门的安全通道，不以公式为由允许文档原始脚本执行。
- 两套现有 Markdown 引擎使用相同语料验证。未支持的引擎或环境明确标记源码降级，不宣称已经满足本阶段双端目标。

任务列表、代码块、引用和基础表格继续保真回归；脚注、自动公式编号、交叉引用、Mermaid 留到后续反馈，不与公式支持捆绑。

## 8. F06–F08：导出是独立交付流程

### 8.1 共用导出约定（F06）

“导出…”始终提供已有 HTML 能力；PDF、Word（DOCX）按对应插件是否启用且就绪动态注册，不硬编码为始终可用。未安装时可显示明确的插件管理入口，不能点击后才发现转换器不存在。首版先完成当前单篇文档；新格式的多篇合集另设子任务，在单篇验收后再做，不能用已有 HTML 合集能力推断 PDF/Word 合集已完成。

- 未保存时明确选择“当前编辑内容”或“磁盘已保存版本”，默认当前编辑内容；生成不可变快照，不替用户保存源文件。导出期间继续编辑也不会混入半份新内容。
- 预检列出缺失图片、未支持公式/语法、失效本地链接、过宽表格及不可用字体。严重错误阻止导出；可降级项提供“返回修改 / 确认按提示导出”。不得悄悄漏掉正文。
- 资源从已授权范围读取，快照包含本次实际采用的附件内容；文件在捕获时变化则重试或提示。外部 URL 默认不抓取，正文和图片不上传转换网站。
- 导出路径不能与源 MD 或其附件为同一文件；要处理大小写、规范化路径及链接别名。目标已存在时显示全路径并确认覆盖，写入前再次核对修订；确认后目标变化须重新确认。
- 在目标同目录写临时文件，生成与基本完整性检查成功后再替换目标。失败或取消保留原目标，只清理本任务临时文件，不删除任何用户资料。
- 耗时任务显示进度阶段、允许取消、支持超时；只有最终文件提交成功才显示成功。错误提供可理解的原因与重试方式，日志不默认收集正文。
- 默认 A4、浅色打印版式，独立于应用三种阅读主题。中文字体替代、边距、代码换行、表格跨页、图片缩放和标题分页有统一模板。
- 核心导出服务接收文档结构、资源快照和选项，不依赖窗口控件，也不分别从两端界面“抓内容”；按 P01 接口调用格式插件。快照、通用预检、目标确认与原子提交留在核心，转换引擎及格式特有规则放在对应插件，不建设外部通用插件 SDK。

### 8.2 PDF 导出插件（F07）

目标是可选择、搜索正文的 PDF，不是逐页截图。标题、列表、代码、图片、表格和公式完整，长文分页稳定。

插件 ID 为 `mdreader.export-pdf`，独立携带并检查其转换依赖；不将浏览器 PDF 引擎加入核心启动依赖，也不要求安装 Word 插件。转换结果先交宿主校验，不直接写最终目标。

优先小样验证“安全 HTML + 打印样式 + 本地浏览器 PDF 引擎”，等待字体、图片与公式渲染完成后生成。Playwright/Chromium 是待验证候选，不是已选定依赖；评估其离线安装、包体积、启动耗时和许可证。不能假定现有 WebView2 即可直接复用这一调用方式。

直接导出 PDF 与“打开打印窗口由用户选择打印机”分开命名和验收。不得把后者冒充本轮直接导出。正文应可检索；若公式采用图片降级，其不可检索限制要写清。

### 8.3 Word DOCX 导出插件（F08）

输出真实 `.docx`：标题映射标题样式，正文和列表可编辑，表格是 Word 表格，图片嵌入文档；不是把 HTML 改名，也不是整篇作为一张图片。

插件 ID 为 `mdreader.export-docx`，独立携带 DOCX 与公式转换依赖；不要求安装 PDF 插件。需要公式图片降级时使用核心约定的公式资源或本插件的转换能力，不能隐式调用一个未安装的 PDF 插件。

公式优先转换为可编辑的 Office Math（OMML）。先验证本轮承诺的公式样本及转换链路，不把“能生成 MathML”等同于“能正确生成 OMML”。不支持的表达式可在用户确认后降级为清晰图片并保留 TeX 替代说明，导出结果列出降级项，不宣称全部公式可编辑。

生成过程不要求安装 Word，不调用云服务；选定具体库、转换器及许可证后记录版本。完成验收包含真实 Word 或 WPS 打开、修改与另存；只解压 XML 不足以证明布局正确。仅测试其中一个时明确记录另一环境未覆盖。
