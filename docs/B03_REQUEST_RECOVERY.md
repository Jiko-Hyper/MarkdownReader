# B03：AI 请求失败后继续工作

日期：2026-10-01。目标版本：桌面测试版 0.4.8。

状态：实现与桌面测试版同步完成；自动检查和随带运行环境复验通过，真人试用待开展。

场景：发送失败后，用户需要修正连接设置再试，或者先切换服务商继续工作；原输入和发送范围不能丢失，也不能把上一次文档的内容误发到下一次请求里。

## 本轮实现

失败后显示「重试上次请求」。用户主动点击才会重新发送，按钮说明可能再次计费。等待中按钮禁用，快速连点也不会重复发送。失败请求不进入成功对话历史，重试成功后只追加一组问题与回复。

重试使用原问题、对话上下文和发送内容，读取用户最新保存的连接配置。输入、附上文档选项或选区发送范围发生变化时，要求通过现有发送或选区修改按钮发起新请求。文档身份、全文版本或选区范围变化时，阻止重发旧内容；保留输入供用户调整。

每个服务商分别保留未发送输入、附上文档选项、选区范围选项和失败请求。切换服务商再回来可以继续编辑。新对话清除当前服务商的失败请求与对话历史，保留未发送输入。连接测试和获取模型不会替换上次失败的文档请求。

所有恢复状态仅保留在当前助手窗口，不写入磁盘。关闭窗口清理待处理回调和恢复状态，不宣称已经取消服务商收到的请求。本轮只提供桌面入口，不改网页请求流程，不新增快捷键或依赖。

实际窗口复验发现失败提示可能挤掉底部发送按钮，已调整为先为输入和操作区域分配空间，对话记录使用剩余空间；窗口位置限制在屏幕内。关闭时主动断开恢复控制器与界面的循环引用。

## 一并修复的选区偏移

真实控件测试发现 Tk 对表情符号计数使用两个单位，而正文切片按一个字符处理，可能把选区后的换行算入发送内容。控件索引与正文字符偏移现统一转换，反向定位复用已有 Unicode 控件索引方法。包含表情、表情之后的选区、应用结果的选中范围及一次撤销均实测。

涉及模块：`ai_recovery.py` 管理窗口内草稿和重试校验；`ai_assistant_ui.py` 接入成功/失败回调；`winui.py` 修正字符偏移。沿用已有请求校验、密钥保护和编辑提交。
