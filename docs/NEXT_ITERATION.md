## 3. E01 连续编辑与撤销重做

状态：**已完成（0.2.8）**。实现与验证结果见 [迭代记录](ROADMAP.md) 的 0.2.8 小节；下面保留原始任务定义与验收条件，作为回归依据。

### 用户问题与目标

0.2.7 在保存和切换主题后能继续撤销，但在预览与源码间切换，或切换到另一份文档后，撤销历史会清空。用户阅读自己的修改再返回时，可能无法撤销刚才的编辑。

目标：每份打开的文档保留自己的编辑内容、撤销重做、光标和选区。预览和标签切换不清空这些状态。重启后恢复撤销历史不在本次范围内。

### 实现范围

- 优先评估每个原生标签持有独立源码编辑控件、预览单独展示的方案，利用 Tk 原生撤销栈。也可采用有明确验证依据的等价实现，不自行重写完整文本编辑器。
- 切换标签只激活对应编辑状态，渲染预览不通过重置源码控件内容完成。
- 保存基线与撤销栈分开管理。撤销到已保存内容时去掉未保存标记；重做离开保存基线时恢复标记。
- 另存为成功后延续当前标签的历史；明确重新加载磁盘内容时可重置历史，但须先处理未保存修改并说明行为。
- 标签关闭后释放编辑控件、事件绑定和计时器。输入法适配继续使用现有顶层窗口桥接，不为每个标签重复安装原生钩子。
- 网页端没有多标签，不新增多标签功能；验证当前文档在阅读与源码间切换时保留编辑和撤销，不因原生改造退化。
- 所有写盘继续经过 `documents.py` 和现有恢复、冲突流程，不另建保存通道。

涉及：`winui.py`、`document_ui.py`、`ime.py` 的控件生命周期及相关窗口测试；网页仅在验证发现同类问题时调整。

### 验收

1. 输入两段文字，源码 → 预览 → 源码，撤销、重做均恢复精确文本。
2. A、B 两标签分别输入不同内容，A → B → A 后撤销只影响 A，B 的内容、光标和历史不改变。
3. 保存后追加文字再撤销，内容回到保存基线时未保存标记正确；重做后标记恢复。
4. 未确认拼音不进入正文或撤销记录；切换标签、主题和关闭窗口后无重复上屏或崩溃。
5. 保存失败、冲突取消、另存取消后继续撤销和重做，磁盘原文件未被误写。
6. 打开约 20 个普通文档再逐一关闭，控件、计时器和输入法注册项回收；记录内存变化，不要求进程内存立即精确回到初值。

替换 `tests/test_document_ui.py` 中“切换后清空撤销”的已知限制断言为新的正向行为用例，同时保留跨文档不串内容的保护。通过后再从使用说明移除该限制。不能只删掉旧测试来宣告完成。

实现方式与任务定义略有不同：不是“为每个标签创建编辑控件后再卸载”，而是**始终每标签一个控件、按需创建、关闭即销毁**，预览单独一份只读控件；输入法从“每控件一个轮询定时器”改为“窗口一个共享轮询循环”（原因与取舍见 `ROADMAP.md` 0.2.8 小节）。内存未做进程级精确回归，只验证控件、适配项与计时器数量回落（原始要求即“不要求立即精确回到初值”）。

## 4. E02 阅读设置入口与持久化

### 用户问题与目标

原生端已有 Ctrl+滚轮调字号，但缺少统一、容易找到并在重启后保留的完整设置流程。用户不应每次重新调整到舒适字号。

首批提供“更多 → 阅读设置”：正文字号、行距、恢复默认。沿用现有主题选择和同步。字体选择、代码字体、阅读宽度作为后续候选，不塞进第一版设置页。

### 实现范围

- 阅读参数进入现有工作区 `ui-settings.json`，通过现有设置服务读取、更新；不改 Markdown 正文或导出模板。
- 旧配置只有主题时使用兼容默认值；更新字号时保留主题、其他设置和未知字段。客户端发局部更新，服务端合并与写入应协调，避免两端设置互相覆盖。
- 明确字号单位和 DPI 换算，原生与网页采用对应的逻辑字号，不承诺不同渲染器字形逐像素相同。
- 保留原生 Ctrl+滚轮并接到同一设置通道；网页不强行覆盖浏览器原生缩放快捷键。
- 同一工作区任一端修改后，另一端按现有同步机制跟随，重启后保持。配置读取或写入失败时显示原因，当前阅读仍可继续。
- 控件变化不重建编辑内容；正文与表格刷新后尽量保留当前可见段落。输入法组合浮层继续跟随编辑字体。

涉及：`core.py` 设置函数及 API、原生设置入口、网页样式和设置界面。当前 `read_ui_settings()` 只返回主题，新增字段必须同时覆盖读取与写入，不能仅在界面保存一个本地值。

### 验收

旧配置启动正确；修改参数后两端可见；重启恢复；恢复默认只重置阅读参数；未保存内容、撤销历史和中文组合状态保留；参数越界或配置损坏有合理降级；100%/150%/200% 缩放分别记录实际验证范围。导出保持既有排版，除非未来单独提供导出设置。

## 5. E03 当前文档查找替换

### 用户问题与目标

用户需要在当前 Markdown 中统一替换一个词，而不必切到外部编辑器。现有查找继续保留，新入口使用源码编辑模式的“替换”面板，建议 Ctrl+H，并实测目标浏览器是否将其交给页面；不可用时按钮入口仍必须可用且说明真实快捷键支持。

### 实现范围

- 支持普通文本查找、上一处/下一处、替换当前、全部替换，范围仅为当前文档。
- 默认区分大小写，明确显示这一规则；首版不做正则、多文件或全项目替换。
- 空查找词禁止执行；空替换文本允许，含义是删除匹配内容。
- 批量匹配按原始文本快照进行非重叠替换，不再次处理新插入的文本。`aaa` 中用 `b` 替换 `aa`，结果为 `ba`。
- 全部替换前显示匹配次数、范围及明确执行按钮；执行期间若原文已变化，重新计算或提示，不用旧位置修改新内容。
- 替换仅修改编辑缓冲并触发现有恢复快照，不自动保存。全部替换作为一个撤销动作，重做也作为一个动作。
- 从阅读界面发起时明确切到源码，不直接修改渲染 HTML。代码、链接等也属于源码，提示这是文本替换，不做语义修复。

涉及：`document_ui.py`、原生编辑命令、`app.js` 查找逻辑与网页控件。不要直接复用允许重叠命中的查找位置列表做原地批量替换；为上述非重叠规则单独建立行为验证。

### 验收

中文、英文、Emoji、跨行文本、无匹配、空输入和替换文本包含查找词的情况均有明确定义；全部替换后一次撤销精确还原；主题或视图切换后还能撤销；Ctrl+S 继续做外部修改冲突检测。两端使用相同语料，结果一致，原文编码和换行保存规则不改变。

## 6. 候选功能的最小范围

### E04 收藏与固定文档

进入条件：试用者反复从最近记录或项目树寻找同一批文件。

最小范围为收藏、取消收藏、统一入口和失效提示。项目文档用工作区加项目身份定位，临时文件用规范化路径定位；同名文件不能合并。收藏元数据旁路存储，不复制正文，取消收藏不删除文件。应用内移动和改名同步更新引用，应用外路径变化只标记失效，不扫描全盘。标签、知识图谱和全文索引不随之引入。

### E05 本地图片插入

进入条件：用户在写笔记时频繁手工复制图片、填写相对路径。

先支持选择本地 PNG/JPEG 并插入相对链接，随后才评估拖放和截图粘贴。临时文档使用同目录下的附件子目录，项目文档使用项目附件目录；草稿先明确文档保存位置。文件复制成功后插入链接，不覆盖同名附件，不移动图片原件。取消、写入失败及插入失败时保留正文；失败时仅清理本次创建且尚未被引用的文件。

撤销插入只撤销文本，不自动删除可能已被其他文档使用的附件。首版不做自动附件清理、远程图片下载、SVG 脚本支持或全库链接重写。原生预览、网页显示、相对路径授权和离线 HTML 导出必须一起验证，不仅检查磁盘里是否出现了图片。

### E06 换主题不丢阅读位置

进入条件：维护者按现有反馈排期，或试用者报告“读长文时换主题找不到原来的位置”。这是 0.2.7 起就存在的既有缺陷（0.2.8 测到的对照数据见 `DEVELOPMENT.md` §3.3），不是 E01 引入的。

最小范围：只在预览（阅读）状态下换主题时，把当前顶部段落恢复回去；不改变主题取值、不动字体度量、不承诺像素级精确（沿用 5.4 的“合理降级到附近位置”）。实现要避免用分数位置直接 `yview_moveto`——重排后行度量会变，应按行号或恢复两次；验收必须包含长文换主题前后顶部行号对比，以及与 E01 的撤销/标签行为不互相影响。与 E01 分开验收，便于判断来源。

### E07 收起侧栏后焦点留在隐藏的搜索框

进入条件：维护者按现有反馈排期。这是 0.2.7 与 0.2.8 相同的既有缺陷，不是 E01 引入的。

复现：在正文里编辑 → 鼠标点一下侧栏「搜索」框 → 按 Ctrl+B 收起侧栏 → 继续打字。实测 `winfo_ismapped()` 为假的那个输入框仍然持有 Tk 焦点，字符进入隐藏的搜索词（`'' → 'a'`），正文不变；同时窗口钩子认定的组合归属者仍是隐藏控件的适配项，拼音没有可见的落点。

最小范围：隐藏侧栏时，如果当前焦点位于侧栏内，把焦点交回正文（源码用编辑控件，预览用只读控件），并清掉搜索适配项的焦点状态；不改变搜索功能本身、不引入新的快捷键。验收要覆盖：收起侧栏后打字进正文、`hook.owner()` 不再是隐藏控件、展开侧栏后点进去仍能正常搜索；并保留“用户主动点搜索框时组合归搜索框”这一正常行为。

### D01 独立分发

进入条件：至少有一位目标试用者因缺少 Python/tkinter 无法完成安装，或维护者明确要求免依赖交付。先做一个打包验证任务，再选发布形式，不先重写 UI。

完成门槛：无开发环境的 Windows 电脑上安装、启动、中文输入、原生桥加载、打开保存、升级回退和卸载保留文档全部验证；记录包大小与冷启动。未达到门槛前继续标记为源码分发包，不把能解压运行等同于独立 EXE。

当时将公式、Mermaid 和新导出格式留在候选池。2026-09-25 维护者明确提出公式与 Word/PDF 导出后，这两项以及图片插入已进入 [新阶段必做范围](NEXT_AUTHORING.md)；Mermaid 仍为候选。实施仍须覆盖离线依赖、原生呈现、网页呈现及导出。

## 7. T01 小范围试用与反馈

建议首批 5 至 10 人、连续使用约一周；人数和周期是试用建议，尚未联系或招募用户。维护者负责邀请与收集反馈，开发负责复现、分级和处理。目标电脑暂时不可用时，继续 E01，不伪造该环境通过。

每位试用者优先完成：打开自己的 Markdown、查找标题或关键词、编辑后预览并返回、保存和重启、整理资料、导出给其他人阅读。记录是否需要额外指导及实际阻碍，不默认上传正文或启用遥测。

| 记录项 | 内容 |
| --- | --- |
| 环境 | 程序版本、Windows 版本、缩放、输入法、原生或浏览器入口 |
| 用户任务 | 当时想完成什么，操作步骤是什么 |
| 实际结果 | 是否完成、是否需要帮助、是否可稳定复现 |
| 影响 | 丢内容或覆盖、核心流程阻断、效率问题、功能建议 |
| 证据 | 脱敏样本、用户自愿提供的截图或错误信息 |
| 跟进 | 任务编号、负责人、状态、修复版本、复验结果 |

P0 数据问题或 P1 核心流程阻断立即插队；其他新功能以重复出现的需求或一个明确阻断工作流的案例为依据。每轮汇总最影响使用的三项问题，无需为没有反馈的功能强行安排发布日期。

## 8. 交付与验证

每项任务沿用 [开发流程](DEVELOPMENT.md)。先做针对性回归，发布前运行统一检查和受影响的真实界面验收。四项 0.2.7 人工验收作为回归基线：拼音与候选位置、双端主题、网页查找目录与阅读位置、冲突和同名导出确认。

修改编辑控件时重点复验输入法、恢复和保存；修改设置时重点复验双端同步与配置兼容；修改替换时重点复验撤销和字符位置。环境未覆盖的项如实保留，不仅凭静态绑定就宣称真实浏览器快捷键已验收。

测试工作区按任务独立命名，启动真实程序必须显式传入 `--workspace`。完整检查的清理目标仍有共享名称，不并发运行完整检查；不能删除其他正在运行的复验会话。发布记录保留在 `docs/`。

任务完成后更新本表状态、`ROADMAP.md` 和相关使用说明。本文件负责下一阶段范围与顺序，不重复保存完整测试日志。
