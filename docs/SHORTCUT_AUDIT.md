# 0.4.12 快捷键验收

## 2026-10-14 / 0.4.15 定位专项复核

此前简单文字用例的通过不能证明复杂文档定位正确。已复现预览第二个 `label` 被定位到 Markdown 链接 URL 内同名文字、强调标记拆分英文单词后跳到下一词的问题。本轮在匹配前建立可见文字与源码偏移的投影，排除隐藏链接地址，保留代码、实体及嵌入对象的对应关系，并增加双向、长重复文档和真实控件回归。

正文定位快捷键改为 `Ctrl+Shift+E`；Shift+M 恢复为普通大写文字输入。无选区时定位当前光标或阅读位置，普通 `Ctrl+E` 仍恢复独立阅读位置。旧版本验收记录保留在下文，当前快捷键以 0.4.15 的说明为准。

检查对象是桌面测试版使用的同一份源码及随带 Python 运行时，不操作用户文档。完整安装包保留离线扫描组件。此次只更新本地，不发布 GitHub。

## 修复

- 应用快捷键在 Tk 文本控件默认编辑动作之前处理，避免 Ctrl+O 插入换行、插入表格组合键变成文本转置。
- 同时处理大小写按键；Caps Lock 不影响 Ctrl+S、Ctrl+Shift+S 和 Ctrl+Shift+T 等操作。普通快捷键不代替未分配的 Shift/Alt 组合。
- 项目 Ctrl+M 不再抢占 Ctrl+Shift+M；Ctrl+Y 仍依焦点区分正文重做与项目地址。
- 扫描页码弹窗补上 Enter 开始、Esc 取消；标题导航支持 Esc 关闭、Enter 跳转；说明补全另存为、标题导航、查找前后匹配及焦点范围。
- 网页视图弹窗、输入法组合和已处理的按键不再触发后台文档操作。

## 真实控件与按键检查

`tests/test_shortcuts.py` 使用 Windows 虚拟键码及 Ctrl/Shift/Caps Lock 状态产生 Tk 按键事件，不仅检查是否存在绑定。

| 范围 | 验证方式 |
| --- | --- |
| 全局操作 | 主窗、源码、预览、搜索输入框、项目树、原文件夹树、最近打开列表、项目下拉框，11 种快捷键 × 两种 Caps Lock 状态，共 176 个组合；每次只分发一次，不意外修改正文或移动光标 |
| 保存与标签 | 实际新建、写盘、另存为、刷新、关闭与切换标签，使用隔离文件 |
| 编辑 | 实际撤销/重做、Delete、表格和公式插入、截图插入流程与选区切换 |
| 导航 | 查找、Enter/Shift+Enter、Esc、标题导航、首尾定位、缩放、侧栏切换 |
| 项目操作 | 实际按键重命名并检查磁盘，查看地址，删除取消与确认；回收站以测试目录代替，不删除用户文件 |
| 最近记录 | Enter 打开与 Delete 移除记录，检查原文件保留 |
| 弹窗 | 输入框按 Ctrl+S/N 不操作背后的正文 |

`tests/shortcuts.test.cjs` 覆盖网页快捷键 Ctrl/Meta、大小写的 32 个有效组合，以及弹窗、输入法组合、AltGr、已处理事件和未分配 Shift 组合的隔离。图片来源、文件选择和确认结果由测试提供，不读取用户剪贴板，不调用付费服务。

普通文字输入、系统文件对话框和浏览器保留键仍由各自控件/系统处理；此记录不把操作系统全部组合键列为 MDReader 快捷键。
