## 本轮范围

用户场景：打开收到的 Markdown，保留中文、列表、表格、图片和代码，交付 Word/PDF。

现状问题：已有导出测试覆盖典型文档、公式和字形，但缺少固定的 20 份以上交付样本及逐样本结论。生成文件成功不能证明内容完整。

最小交付：自行编写、可公开的固定样本和预期结果；通过宿主 API 和实际插件包导出；核验正文、表格单元格、图片及源文件不变；渲染页面供视觉验收；登记并优先修复内容丢失。

暂不包含：A02 的五名首次用户试用、B01 选区 AI、导出模板重做、独立安装包发布。真人试用不以自动测试冒充。

涉及：`tests/fixtures/delivery/`、`tools/verify_delivery.py`、`plugins/official/common/exporting.py`、相关插件打包与回归。

失败分支：缺图、损坏图片、空文档、预检取消、已有目标、未保存编辑、源文件保持不变。现已加入确认覆盖后失败保留旧文件、官方插件取消、完成后未提交时取消及真实 Tk 取消按钮测试；不将程序驱动的真实控件测试称为真人试用。

## 验收入口

在 `MarkdownReader/` 运行 `python tools/verify_delivery.py`。每次创建独立 `.testtmp/delivery-*` 目录，保留输入副本、产物、机器报告和逐页 PNG。检查失败返回非零退出码；已知降级独立列出，不计为保真通过。视觉验收状态默认待验收，不能由文本检查自动置为通过。

`report.md` 除逐样本结论外，还输出逐页记录（页号、可见字符数、图片数、本页机器问题），供逐页对照 `samples/*-page-*.png`。Word 端运行 `pwsh -File tools/render_delivery_word.ps1 -EvidenceDir <证据目录>`（要求本机装有 Word，Python 有 pypdfium2），生成 PDF、PNG 及页面清单。本轮已成功生成并查看 25 页。实际观察独立保存于 [逐页视觉复核记录](A01_VISUAL_REVIEW.md)。

样本由本项目自行编写，不包含用户原文或个人信息。预期字段与输入一起版本控制。
