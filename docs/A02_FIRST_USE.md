# A02 首次使用流程

日期：2026-09-27。负责人：本次开发任务。基线：0.4.0；目标：下一次维护更新，尚未发布。状态：待验收（桌面增量已实现，真人观察未做）。

用户场景：首次打开 Markdown，编辑后离线交付 Word/PDF。

现状：打开文件已有侧栏入口，AI 已有工具栏入口；导出藏在更多菜单，缺少插件时只进入通用管理，完成后只有路径提示。

最小交付：桌面工具栏固定导出入口、按格式安装或启用随包插件、完成后打开产物或定位所在文件夹。复用统一导出预检、覆盖确认和取消流程。

暂不包含：界面整体重做、网页端新增入口、在线插件市场、自动联网或自动配置 AI。没有真人观察前不声称已找出用户的前三个阻碍。

涉及：export_ui.py、winui.py、PluginStore、真实 Tk 回归。

验证范围：无 AI 配置的离线导出；缺插件、停用插件、缺随包文件、受信校验失败、用户取消安装、目标被移动；切换文档后完成按钮仍指向实际产物。

## 已实现的桌面流程

1. 工具栏固定「导出 Word/PDF」入口，菜单显示当前文档名称，复用既有文档快照、来源选择、预检、覆盖确认与取消流程。
2. 缺少插件时，由用户点击「安装并启用」从随包目录安装所选格式；走原有 PluginStore 哈希、兼容与依赖检查，不联网，不绕过受信校验。已有但停用的插件只启用，不重装。失败在同一窗口显示原因并保留插件管理入口。
3. 启用后不自动导出，用户重新确认当前文档再发起。导出完成窗口绑定实际结果路径，显示原文档名称与降级提示，提供打开文件/定位所在文件夹；文件已被移动时给出明确错误。
4. 安装和完成窗口居中并使用当前主题。源码中的新增界面逻辑放在 `mdreader/export_ui.py`，未在主窗口堆叠独立实现。
